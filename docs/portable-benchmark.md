# Переносимая проверка графики

Команды входят в обычный JAR мода. Нужны та же сборка, Minecraft 1.20.1,
Forge 47.2.18, Java 17 и Veil 1.0.0.296. Разработческий запуск или Gradle
на компьютере тестировщика не нужны.

## Что передать тестировщику

Замените старый JAR Maniac Revolution новым, оставив Veil и остальные моды.
Передайте ту же карту. Откройте **копию карты в одиночном мире вне матча**.
Встроенные точки предназначены для нашей карты: комната и два направления
в особняке, затем участок около пиццерии. В другом мире используйте свой маршрут.

Для обычной проверки достаточно:

```text
/mrbench start
```

Это около пяти минут: четыре ракурса, пять режимов, два повтора в текущем
разрешении. Порядок режимов на втором повторе обратный. Перед каждым замером
идёт прогрев 3 секунды, затем запись 4 секунды. Точное число этапов и оценка
времени выводятся при старте. Ничего не нажимайте и не сворачивайте игру.

Для проверки зависимости от разрешения:

```text
/mrbench start matrix
```

Помимо текущего разрешения добавляются 1280×720 и 1920×1080, если они
не превышают исходное и не дублируют его. Используется настоящее изменение
размера окна; запросы переводятся в логические размеры с учётом HiDPI.
Фактический размер буфера и режим окна записываются для каждого этапа.
Для уменьшенных разрешений игра временно переходит в оконный режим.
Такой запуск может занять до 15 минут.

В конце игра пишет в локальный чат абсолютный путь к одному ZIP и показывает
ссылку «Открыть папку с результатом». Файл находится в
`benchmark-results/mrbench-<дата>-<id>.zip` внутри папки экземпляра Minecraft.
Тестировщик отправляет именно этот ZIP — его можно затем передать для анализа.
Отчёт никуда не отправляется автоматически.

Остановить раньше:

```text
/mrbench stop
```

Открытие меню, потеря фокуса, изменение камеры/разрешения пользователем,
перемещение или начало матча также прерывают измерение. Уже собранные данные
сохраняются; незавершённый этап помечается отдельно. Настройки окна, VSync,
лимит FPS, камера, HUD/чат и положение, режим и способности игрока возвращаются.
Временно замороженные цикл суток, погода, спавн и случайные тики восстанавливаются.
Содержимое инвентаря и блоки не меняются.

## Режимы проверки

| Имя в отчёте | Что проверяется |
| --- | --- |
| `VEIL_RENDER_BYPASS` | Обход выбранных служб рендера Veil |
| `OFF` | Обычная настройка графики «Отключить», Veil работает штатно |
| `LIGHT` | Лёгкая атмосфера |
| `NORMAL` | Обычная атмосфера |
| `HEAVY` | Тяжёлая атмосфера с контактными тенями |

**Выгрузить Veil из работающей JVM целиком нельзя.** Обход отключает начало/
конец его кадра, постобработку, отдельный проход руки, обновление данных камеры
и GUI. JAR, выделенные ресурсы, прочие mixin-перехваты и некоторые обработчики
остаются загружены. Поэтому `VEIL_RENDER_BYPASS` честно обозначен как обход
рендера, а не как клиент без библиотеки. Для точного сравнения с удалённым
Veil нужен другой запуск клиента; предыдущая методика описана в
[veil-overhead.md](veil-overhead.md).

Каждый этап обхода проверяет выполнение всех четырёх групп перехватов.
Если они не работают, отчёт помечается ошибкой, а не выдаёт ложный baseline.
Проверка не запускается при активном Veil Deferred или стороннем эффекте Veil.

Ручное переключение вне матча в одиночном мире:

```text
/mrbench veil off
/mrbench veil on
```

Первая команда включает диагностический обход, вторая возвращает обычную
работу библиотеки. При выходе из мира или начале матча обход снимается.
Обычная настройка «Отключить» автоматически обход не включает.

## Другие точки

```text
/mrbench points
/mrbench points clear
/mrbench points add corridor
/mrbench points add lamps
/mrbench points reset
```

`add` сохраняет текущее положение и направление взгляда. Чтобы построить
свой маршрут, сначала очистите список, затем встаньте в каждую нужную точку
и добавьте её. `reset` возвращает четыре встроенных ракурса. Все точки должны
находиться в текущем измерении. Маршрут хранится в
`config/maniacrev-benchmark-points.json`; его можно передать вместе со сборкой.
Тест не переходит в другой мир и не ищет подходящую карту по имени.

## Что записано в ZIP

- `report.json`: CPU, физические/логические ядра, RAM, GPU и VRAM, OpenGL/
  драйвер, ОС, Java и лимит памяти JVM; версии модов и ресурс-паки;
  отпечаток бенчмарка и основных шейдеров; исходные/тестовые/восстановленные
  настройки, маршрут, фактические разрешения, число источников, GC,
  сводки и предупреждения.
- `frames.csv`: интервалы отдельных кадров, длительность участка рендера
  на стороне приложения и асинхронные GPU-замеры.
- `README.txt`: единицы измерения и ограничения интерпретации.

Имя игрока, UUID, seed мира, адрес сервера, токены и полная командная строка
Java в файл не включаются. Тест работает локально и временно переопределяет
графику без сохранения этих переопределений в настройках матча.

FPS рассчитывается по реальным интервалам кадров. GPU-таймер охватывает
RenderTick START–END, включая мир, руку, HUD и постобработку, но не весь
показ кадра и все внешние обработчики. «1% low» определён как 1000 / p99
интервала. При отсутствии GPU-таймеров остальные данные всё равно сохраняются.
Потолок FPS, динамические частоты и короткая выборка могут скрыть небольшую
разницу; предупреждения о них также входят в файл.

Для локальной текстовой сводки на компьютере разработчика:

```powershell
python tools/analyze_mrbench.py путь-к-файлу.zip
```

Проверки реализации:

```powershell
.\gradlew.bat verifyAtmosphereBenchmark --no-daemon
.\gradlew.bat -I tools/benchmark-smoke.gradle runClient -x processResources --no-daemon
```

Для второго запуска заранее создайте копию карты под именем
`run/benchmark-smoke-client/saves/perf-map`. Smoke-проверка использует короткие
интервалы для проверки функций и явно отмечается `smoke_test: true` в отчёте;
её числа не предназначены для сравнения производительности железа.
